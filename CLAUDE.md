# LectureLoop (scholar-sum-notes)

Individual class-notes app: each student takes their own notes per class (typed or
handwritten, next to the lecture slides) and gets an AI summary of their own notes.
There is no shared/class-wide summary. Originally generated with Lovable; now maintained directly
in this repo with no Lovable dependency.

## Stack

- TanStack Start (React 19 UI + server functions in one codebase), Vite 8, nitro for deploy output
- Tailwind CSS v4 + shadcn/ui (`src/components/ui`)
- Supabase (Postgres, auth, storage) via `@supabase/supabase-js`
- AI via any OpenAI-compatible endpoint (`src/lib/ai-gateway.server.ts`)

## Commands

- `bun install` (bun.lock is the lockfile; `npm install` also works)
- `bun run dev` → http://localhost:8080
- `bun run build` → `.output/`
- `bun run typecheck` — must pass before committing
- `bun run lint` / `bun run format`

## Layout

- `src/routes/` — file-based routes; `src/routeTree.gen.ts` is generated by the router plugin, don't hand-edit
- `src/routes/_authenticated/` — pages behind sign-in
- `src/lib/*.functions.ts` — server functions (backend API); `*.server.ts` is server-only
- `src/integrations/supabase/` — browser client, server client, auth middleware, generated `types.ts`
- `supabase/migrations/` — database schema, apply in filename order

## How every requirement is delivered (required)

For every new requirement or change request, follow `docs/process/REQUIREMENTS_PROCESS.md`:

1. **Requirement analyst** (main session): `node scripts/req/new.mjs "<title>" "<request>"`, then
   fill in `requirement.md` with scope, user stories and numbered acceptance criteria (AC-1…).
2. **Developer agent** builds it on `claude/<slug>` from `preprod`, using only the requirement.
3. **Test master agent** writes `test-cases.json` from the requirement only (not the code),
   covering every acceptance criterion.
4. **Tester agent** runs every test case (test data or mocks only), saves screenshots to
   `evidence/`, writes `test-results.json`, and runs `node scripts/req/evidence.mjs <folder>`
   to produce `test-evidence.xlsx`.
5. **Product manager agent** checks the requirement against the working feature and the
   evidence, and records Approved or Changes requested in `requirement.md`.
6. Only after approval: commit the requirement folder with the code and raise the PR into
   `preprod`.

Use a separate agent (Agent tool) for each of the developer, test master, tester and product
manager roles. Record every step with `node scripts/req/audit.mjs <folder> "<Role>" "<Action>"
"<Details>"`. The user can waive steps 3–5 for a trivial change; record that in the audit trail.

## Conventions

- Use the `@/` alias for imports from `src`.
- Never import `*.server.ts` modules from client code (the build fails on it).
- Secrets (`SUPABASE_SERVICE_ROLE_KEY`, AI keys) are server-only env vars; only `VITE_*` vars reach the browser.
- Open PRs against `preprod`, never `main`. `preprod` deploys to
  https://lectureloop-preprod.vercel.app for testing; a release PR `preprod` → `main` takes it
  live (see "Release flow" in `DEPLOYMENT.md`). Pre-prod shares the live database.
- See `AGENTS.md` for UI notes and `DEPLOYMENT.md` for hosting.
